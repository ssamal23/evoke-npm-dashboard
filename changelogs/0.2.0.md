# Evoke UI Kit: Integration Skill

The Evoke UI kit is built with **Stencil.js** and published to **npm** as `@evoke-tech/stencil-ui-kit`: framework-agnostic web components (tags start with `evoke-`) that work in React, Angular, Vue and plain HTML. To keep components behaving consistently with each project's setup, every integration must state **which framework** and **which styling system** it uses before any code is written.

Names used in this skill:
- Package: `@evoke-tech/stencil-ui-kit` (current version 0.2.0, 20 components)
- Component tag prefix: `evoke-` (for example `<evoke-button>`)
- CSS custom property (token) prefix: `--evoke-`
- Check the Evoke version dashboard for what each release was tested with.

---

## Step 1: Declare the project setup (required, always first)

Before generating any UI or code, state the setup in this exact format at the top of the response or file:

```
Framework: React | Angular | Vue | Plain HTML
Styling:   Tailwind CSS | Bootstrap | Angular Material | Vanilla CSS
Design system: @evoke-tech/stencil-ui-kit (Stencil.js web components)
```
(Keep only the one value that applies on each line.)

Supported combinations:

| Framework  | Styling options                                   |
|------------|---------------------------------------------------|
| Angular    | Angular Material, Tailwind CSS, Bootstrap, Vanilla CSS |
| Vue        | Tailwind CSS, Bootstrap, Vanilla CSS              |
| React      | Tailwind CSS, Bootstrap, Vanilla CSS              |
| Plain HTML | Bootstrap, Vanilla CSS (Tailwind only if the project already has a Tailwind build step) |

Angular Material works only in Angular. If it is requested with another framework, say so and ask which styling system to use instead.

Rules:
- If the user has not specified the framework or the styling system, **ask**. Do not guess.
- If the project already exists, detect it from `package.json` and config files:
  - Framework: `@angular/core` (Angular), `vue` (Vue), `react` (React), none of these (Plain HTML).
  - Styling: `@angular/material` means Angular Material; `bootstrap` means Bootstrap; `tailwind.config.*`, `@tailwind` or `@import "tailwindcss"` in CSS, or `tailwindcss` in `package.json` means Tailwind. Otherwise assume Vanilla CSS and say so.
- Never mix styling systems in one project. Pick one and stay with it.
- What has been tested (version 0.2.0): Angular 22 with Tailwind 4, Bootstrap 5.3 and Angular Material (M3); Vue 3.5 with Tailwind 4 and Bootstrap 5.3; Plain HTML in Chromium. **React has not been run in a real app yet** (status "Expected"). If the user asks whether a combination is supported, say whether it was tested, and report any problem you find.

## Step 2: Install and register the components

```bash
npm install @evoke-tech/stencil-ui-kit
```

### 2a. Styles (all frameworks)

Import the base tokens/styles **once** in the global stylesheet, then **one** theme file for the chosen styling system, **after** the base file:

| Styling | Imports in the global stylesheet |
|---|---|
| Vanilla CSS | `@import '@evoke-tech/stencil-ui-kit/dist/evoke-ui/evoke-ui.css';` and override `--evoke-*` yourself |
| Tailwind CSS | base + `@import '@evoke-tech/stencil-ui-kit/themes/tailwind.css';` (maps to Tailwind `--color-*`, `--radius-*`) |
| Bootstrap | base + `@import '@evoke-tech/stencil-ui-kit/themes/bootstrap.css';` (maps to Bootstrap `--bs-*`), with Bootstrap's own CSS loaded as the project already does |
| Angular Material | base + `@import '@evoke-tech/stencil-ui-kit/themes/material.css';` (maps to `--mat-sys-*`) |

```css
/* styles.css, Angular Material example */
@import '@evoke-tech/stencil-ui-kit/dist/evoke-ui/evoke-ui.css';
@import '@evoke-tech/stencil-ui-kit/themes/material.css';
```
(In a JavaScript entry file, such as `main.tsx` or `main.ts`, use `import '@evoke-tech/stencil-ui-kit/dist/evoke-ui/evoke-ui.css';` and the same for the theme file.)

### 2b. Register the components (per framework)

**React**
```tsx
// main.tsx
import { defineCustomElements } from '@evoke-tech/stencil-ui-kit/loader';
defineCustomElements();

<evoke-button variant="danger" onClick={save}>Delete</evoke-button>
```
- **React 19+**: custom elements are fully supported. Objects/arrays pass as properties, `className` works, and custom events work as `onEvokeChange={...}` style props.
- **React 18 and below**: only string attributes pass reliably, and the attribute is `class`, not `className`, on a custom element. For object/array props and custom events, use a `ref`:

```tsx
const ref = useRef<HTMLEvokeSelectElement>(null);
useEffect(() => {
  const el = ref.current;
  if (!el) return;
  el.options = options;                           // set complex props as properties
  const onChange = (e: Event) => setValue((e as CustomEvent).detail);
  el.addEventListener('evokeChange', onChange);   // listen to the component's events
  return () => el.removeEventListener('evokeChange', onChange);
}, [options]);

<evoke-select ref={ref} />
```
- TypeScript does not know the `evoke-*` tags by default. Add a declaration (not yet tested in this kit):

```ts
// evoke.d.ts
declare module 'react' {
  namespace JSX {
    interface IntrinsicElements { [tag: `evoke-${string}`]: any }
  }
}
export {};
```

**Angular**
```ts
// main.ts
import { defineCustomElements } from '@evoke-tech/stencil-ui-kit/loader';
defineCustomElements();

// component (or module): allow the custom tags
@Component({ schemas: [CUSTOM_ELEMENTS_SCHEMA], /* ... */ })
```
```html
<evoke-button variant="primary" (click)="save()">Save</evoke-button>
<evoke-input label="Email" [value]="email" (evokeInput)="email = $event.detail"></evoke-input>
<evoke-select label="Role" [options]="roles" (evokeChange)="role = $event.detail"></evoke-select>
```
- Bind lists as properties (`[options]="roles"`). Read the value from `$event.detail`.
- The kit ships no Angular forms adapter, so do not use `ngModel` or `formControlName` on the tags. Bind `[value]` and handle the event.
- Import the base CSS and one theme in `styles.css` (or `styles.scss`).

**Vue** (Vue 3)

**Published 0.2.0 has no Vue wrappers (`/vue`).** Use the raw tags (below, "Raw tags") for 0.2.0. The wrappers are added in the next release; use them once the installed version includes `@evoke-tech/stencil-ui-kit/vue` (check with `npm view @evoke-tech/stencil-ui-kit version`).

With a release that includes the wrappers (recommended there): they need no compiler setting.
```ts
// main.ts
import { createApp } from 'vue';
import { EvokeUi } from '@evoke-tech/stencil-ui-kit/vue';
import '@evoke-tech/stencil-ui-kit/dist/evoke-ui/evoke-ui.css';

createApp(App).use(EvokeUi).mount('#app'); // registers the custom elements
```
```vue
<script setup>
import { EvokeButton, EvokeInput } from '@evoke-tech/stencil-ui-kit/vue';
</script>
<template>
  <EvokeButton @click="count++">Clicked {{ count }} times</EvokeButton>
  <EvokeInput label="Email" :value="email" @evokeInput="email = $event.detail" />
</template>
```
- There is no `v-model` support. Bind `:value` and handle the event.
- Why wrappers: the components render into the page DOM (no shadow root). With a raw tag such as `<evoke-button>Count: {{ n }}</evoke-button>`, Vue replaces the tag's contents on every update and removes the button's inner markup. The wrappers avoid this.
- **Raw tags** (required for 0.2.0): set `isCustomElement: t => t.startsWith('evoke-')` in the Vue compiler options (for Vite: `vue({ template: { compilerOptions: { isCustomElement: t => t.startsWith('evoke-') } } })`), call `defineCustomElements()` from `@evoke-tech/stencil-ui-kit/loader` in `main.ts`, import the base CSS, and wrap any dynamic text in an element: `<evoke-button><span>{{ n }}</span></evoke-button>`. Events: `@evokeInput="email = $event.detail"`.

**Plain HTML / CDN**
```html
<link rel="stylesheet" href="https://unpkg.com/@evoke-tech/stencil-ui-kit@0.2.0/dist/evoke-ui/evoke-ui.css">
<!-- one theme, after the base file, e.g. Bootstrap -->
<link rel="stylesheet" href="https://unpkg.com/@evoke-tech/stencil-ui-kit@0.2.0/dist/themes/bootstrap.css">
<script type="module" src="https://unpkg.com/@evoke-tech/stencil-ui-kit@0.2.0/dist/evoke-ui/evoke-ui.esm.js"></script>

<evoke-input id="email" label="Email"></evoke-input>
<evoke-select id="role" label="Role" options='[{"label":"Developer","value":"dev"}]'></evoke-select>
<script>
  document.getElementById('email').addEventListener('evokeInput', (e) => console.log(e.detail));
</script>
```
- Pin the version in the URL (`@0.2.0`) so a new release does not change the page by itself.
- List props (`options`, `columns`, `rows`) can be JSON strings in HTML, or arrays set as properties in JavaScript.
- Events: use `addEventListener`; the value is `event.detail`.

### 2c. Props and events

Most-used props (the full list is in `dist/types/components.d.ts`):

| Tag | Props |
|---|---|
| `evoke-button` | `variant` primary, secondary, danger, outline, ghost; `size` sm, md, lg; `disabled`; `loading`; `icon`; `icon-only` (with `accessible-label`); `block`; `button-class` |
| `evoke-input` | `label`, `value`, `type`, `name`, `placeholder`, `appearance` outlined or filled, `error`, `hint`, `icon`, `disabled`, `required`, `input-class` |
| `evoke-select` | `label`, `options`, `placeholder`, `multiple`, `searchable`, `error`, `hint`, `disabled`, `select-class` |

The 20 components are: button, input, select, checkbox, radio-group, textarea, switch, card, alert, modal, tabs, badge, tooltip, toast, table, pagination, chip, progress, app-bar, quantity-stepper.

Events are named `evoke…` in camelCase, and the value is `event.detail`. `evokeChange` is used by input, textarea, select, checkbox, radio-group, switch, tabs, pagination, chip and quantity-stepper; `evokeInput` by input and textarea. Others: `evokeClose` (modal, toast), `evokeDismiss` (alert), `evokeAction` (toast), `evokeSort` (table), `evokeClick` (card), `evokeRemove` (chip). The button uses the native `click`.

## Step 3: Apply the styling system correctly

The Evoke components are built with `shadow: false`, so they render in the **light DOM** (no Shadow DOM). Their inner markup (for example the `<button class="evoke-btn evoke-btn--primary">` inside `<evoke-button>`) sits in the normal page, so outside CSS **can** technically reach it, but that does not make it a good idea. Prefer the component's public API in this order: props, CSS custom properties (tokens), then the `*-class` props that add classes to the inner element. There is no `::part()` and no shadow root: do not use `::part()`, `:host`, `::slotted()` or `shadowRoot` anywhere.

Where the classes go matters:
- A class on the tag (`<evoke-button class="mt-4">`; `className` in React 19) lands on the **host element**, not on the inner `<button>`. Use it for layout only (margin, width, grid or flex placement).
- To add classes to the **inner** element, use the component's class prop: `button-class`, `input-class`, `select-class`, `textarea-class`, `card-class`, `modal-class`. Examples: `<evoke-button button-class="shadow-lg">` (Tailwind), `<evoke-button button-class="btn btn-lg">` (Bootstrap).

### Tokens

Theme with tokens. The base file defines these on `:root`, and each theme file remaps them to that system:

| Group | Tokens |
|---|---|
| Colour | `--evoke-primary`, `--evoke-primary-contrast`, `--evoke-primary-text`, `--evoke-secondary`, `--evoke-secondary-contrast`, `--evoke-danger`, `--evoke-success`, `--evoke-warning`, `--evoke-info` |
| Surface and text | `--evoke-surface`, `--evoke-surface-muted`, `--evoke-text`, `--evoke-text-muted`, `--evoke-border` |
| Shape and size | `--evoke-radius`, `--evoke-radius-field`, `--evoke-radius-button`, `--evoke-control-height`, `--evoke-button-padding-x` |
| Type, focus, shadow | `--evoke-font`, `--evoke-font-size`, `--evoke-focus-ring`, `--evoke-shadow` |

Notes: there are no spacing tokens (`--evoke-space-*` does not exist). Use your own spacing scale. In the default Evoke look, white text on the orange `--evoke-primary` (#ff5316) is only 3.23:1 contrast, and for orange text on a white background use `--evoke-primary-text` (#cc3d0d).

### Common rules (all styling systems)
- Use Evoke components first. Only build custom UI when no component fits, and build it from tokens.
- Use component props (`variant`, `size`, `appearance`, `disabled`, `loading`, etc.) for visual variations. Do not override internal styles.
- Never hard-code colors, radii, or font values that a token already covers.

### Tailwind CSS (React, Angular, Vue)
- Import `themes/tailwind.css` after the base file. It maps the Evoke tokens to Tailwind's theme, so the components follow your Tailwind theme: primary becomes Tailwind blue-600, for example.
- Use Tailwind for **layout and spacing around** components: `flex`, `grid`, `gap-*`, `p-*`, `w-full`, responsive prefixes.
- Do **not** use Tailwind to restyle a component's internals. `class="bg-red-500"` on `<evoke-button>` only styles the host element, so the inner button stays the same colour. Change the colour with a prop (`variant="danger"`) or a token. Use the class props (`button-class`) only for small extras such as `shadow-lg`.
- For your own custom UI, use the tokens through Tailwind so it stays on-brand:

```css
/* Tailwind v4, in your global CSS after the imports */
@theme inline {
  --color-brand: var(--evoke-primary);
  --color-surface: var(--evoke-surface);
  --radius-evoke: var(--evoke-radius);
}
```

```html
<!-- React 19 shown; Angular and Vue use class="..." -->
<div className="flex flex-col gap-4 p-4 bg-surface rounded-evoke">
  <evoke-input label="Email" type="email" />
  <evoke-button variant="primary" className="self-end">Continue</evoke-button>
</div>
```
- Make sure Tailwind's preflight does not fight the system's base styles. If conflicts appear, load the Evoke CSS **after** Tailwind's base layer.

### Bootstrap (React, Angular, Vue, Plain HTML)
- Keep Bootstrap's CSS loaded as the project already does. Import `themes/bootstrap.css` after the Evoke base file. It maps the tokens to Bootstrap's variables (`--bs-primary`, `--bs-border-radius`, `--bs-body-font-family` and so on), so the components follow the Bootstrap theme, including any `--bs-*` overrides you set.
- Use Bootstrap's grid and utilities for **layout around** components: `row`, `col-*`, `d-flex`, `gap-*`, `p-*`, `mb-*`.
- Do not restyle a component's internals with Bootstrap classes on the tag. Use a prop (`variant`) or a token. Use the class props only for extras, such as `button-class="btn btn-lg"` for Bootstrap's large button size.
- Bootstrap's own components (navbar, dropdown) can be used where Evoke has no component, as long as they follow the same tokens.

```html
<div class="d-flex flex-column gap-3 p-3">
  <evoke-input label="Email" type="email"></evoke-input>
  <evoke-button variant="primary" class="align-self-end">Continue</evoke-button>
</div>
```

### Angular Material (Angular only)
- Import `themes/material.css` after the Evoke base file. It maps the tokens to Material 3 system tokens (`--mat-sys-primary`, `--mat-sys-corner-*` and so on), so the components follow your Material theme. Define the theme with Angular Material's own setup (`mat.theme()`).
- Use Evoke components first. Where Evoke has no component, use the matching Angular Material component (for example `mat-toolbar`, `mat-menu`) instead of hand-building one.
- Use Angular layout (flex or grid in your own CSS) around components. Do not restyle a component's internals with Material classes.
- Known issues in 0.2.0 (fixed in the next release): cards and alerts are pill-shaped, and the font falls back to a serif if Roboto is not loaded. Load Roboto in `index.html`.

```html
<div style="display:flex; flex-direction:column; gap:16px; padding:16px">
  <evoke-input label="Email" type="email"></evoke-input>
  <evoke-button variant="primary">Continue</evoke-button>
</div>
```

### Vanilla CSS (all frameworks)
- Use plain CSS files, CSS Modules (React) or component styles (Angular, Vue) for layout.
- Reference tokens directly:

```css
/* SignupForm.module.css */
.form {
  display: flex;
  flex-direction: column;
  gap: 16px;
  padding: 16px;
  background: var(--evoke-surface);
  border: 1px solid var(--evoke-border);
  border-radius: var(--evoke-radius);
}

/* Theme components through public tokens. Tokens set on a parent are inherited by the components inside it */
.dangerZone { --evoke-primary: var(--evoke-danger); }
/* Light DOM: never target internal class names (such as .evoke-btn) or ::part(). They can change between versions. */
```

## Step 4: Check before finishing

- [ ] Setup declaration (Framework + Styling) is present at the top
- [ ] The combination is supported (Angular Material only in Angular), and untested ones (React) are flagged
- [ ] Global Evoke CSS (`evoke-ui.css`) is imported once, plus exactly one theme file if the project uses Tailwind, Bootstrap or Angular Material
- [ ] Components are registered: `defineCustomElements()` (React, Angular, Vue raw tags), `EvokeUi` plugin (Vue wrappers, only in releases after 0.2.0), or the script tag (Plain HTML)
- [ ] Framework specifics are handled: `CUSTOM_ELEMENTS_SCHEMA` (Angular), `isCustomElement` and `<span>` around dynamic text for Vue raw tags (needed in 0.2.0), `ref` and `evokeChange` plus `class` instead of `className` for React 18, JSON strings or properties for list props in Plain HTML
- [ ] Values are read from `event.detail`; no `ngModel`, `formControlName` or `v-model` on the tags
- [ ] Only one styling system is used
- [ ] No attempts to style component internals with classes or selectors; only props, tokens and the `*-class` props (no `::part()`, `:host`, `::slotted()` or shadow-root code, because the components use `shadow: false`)
- [ ] Dynamic text inside a component tag is wrapped in a `<span>` when using raw tags (components render their inner markup in the light DOM, and a lone text child can replace it; seen with Vue, not yet tested with React)
- [ ] No hard-coded values where a token exists

## Notes for Figma Make

Figma Make generates React code, typically with Tailwind CSS, so this section applies to React only. When using this skill there (for example, pasted into the project's guidelines file):
- Begin every generation with the Step 1 declaration. Default to `Framework: React / Styling: Tailwind CSS` unless told otherwise.
- Prefer Evoke components over generic hand-built elements for buttons, inputs, cards, modals, and navigation.
- If the npm package cannot be installed in the environment, keep the same `evoke-*` tag names, props, and `--evoke-*` token names so the output maps 1:1 to the real kit when handed off to development.
