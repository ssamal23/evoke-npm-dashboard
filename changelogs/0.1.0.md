| Framework | Styling options                 |
|-----------|---------------------------------|
| React     | Tailwind CSS **or** Vanilla CSS |

Rules:
- If the styling system is not stated, **ask** the user: Tailwind CSS or Vanilla CSS. Never guess.
- In an existing project, detect it: `tailwind.config.*`, `@tailwind`, `@import "tailwindcss"`, or `tailwindcss` in `package.json` means Tailwind. Otherwise use Vanilla CSS and say so.
- Use only one styling system per project.
- If another framework is requested (Vue, Angular, plain HTML), say this skill does not cover it yet and ask how to proceed.

## 2.2 Installation and setup

```bash
npm install [@your-org/design-system]
# If you publish a React wrapper (preferred):
npm install [@your-org/design-system-react]
```

Import the global stylesheet **once** at the app entry (e.g. `main.tsx`):

```tsx
import '[GLOBAL STYLESHEET PATH]';
```

**Option A – React wrapper (preferred):**

```tsx
import { DsButton } from '[@your-org/design-system-react]';
<DsButton variant="primary" onDsClick={save}>Save</DsButton>
```

**Option B – Raw web components:**

```tsx
import { defineCustomElements } from '[@your-org/design-system]/loader';
defineCustomElements();
// then:
<ds-button variant="primary">Save</ds-button>
```

React version note for Option B:
- **React 19+**: object/array props and custom events (`onDsChange`) work directly.
- **React 18 and below**: pass object/array props and listen to events through a `ref`:

```tsx
const ref = useRef<HTMLDsSelectElement>(null);
useEffect(() => {
  const el = ref.current; if (!el) return;
  el.options = options;
  const handler = (e: CustomEvent) => setValue(e.detail);
  el.addEventListener('dsChange', handler);
  return () => el.removeEventListener('dsChange', handler);
}, [options]);
<ds-select ref={ref} />
```

# PART 4 – Implementation rules

Stencil components render inside **Shadow DOM**. Outside styles, including Tailwind utilities, cannot restyle a component's internals. Style components only through props, tokens (CSS custom properties), slots, and `::part()`.

## Common rules
1. Pick components from 2.3 before writing custom UI. Build custom UI only when nothing fits, and build it from tokens.
2. Use props (`variant`, `size`) for visual variations.
3. Follow the style guide (Part 3) for layout, copy, and accessibility.

## React + Tailwind CSS
- Tailwind handles **layout and spacing around** components (`flex`, `grid`, `gap-*`, `p-*`, responsive prefixes).
- Do not put visual classes on components expecting them to change (e.g. `className="bg-red-500"` on `<ds-button>` does nothing inside).
- Map Tailwind's theme to tokens:

```js
// tailwind.config.js (v3) – or use @theme in Tailwind v4
theme: { extend: {
  colors:  { primary: 'var(--ds-color-primary)', surface: 'var(--ds-color-surface)' },
  spacing: { 'ds-sm': 'var(--ds-space-sm)', 'ds-md': 'var(--ds-space-md)' },
  borderRadius: { ds: 'var(--ds-radius-md)' },
}}
```

- If Tailwind's preflight conflicts with base styles, load the design system CSS after Tailwind's base layer.

## React + Vanilla CSS
- Use CSS files or CSS Modules for layout; reference tokens directly.

```css
.form { display: flex; flex-direction: column; gap: var(--ds-space-md); }
.danger ds-button { --ds-button-bg: var(--ds-color-danger); }
ds-card::part(header) { border-bottom: 1px solid var(--ds-color-border); }
```

## Figma Make notes
- Figma Make outputs React, usually with Tailwind CSS. Default to `Framework: React / Styling: Tailwind CSS` unless told otherwise.
- If the npm package cannot be installed, keep the **exact** component names, props, and token names from Part 2, so the output maps 1:1 to the real system during handoff.
- Match the Figma library named in 2.1 when choosing components and variants.
